# 사방넷 매뉴얼 업데이트 스킬

## 트리거
사용자가 비서(클비서)에게 "노션 사방넷매뉴얼 업데이트해줘" 또는 유사한 표현으로 요청할 때 사용한다.

1. **온보딩 회의록** — Notion "회의록 양식" 데이터소스
   `collection://3a25ef83-8b3e-82df-b3eb-070491bfba49`
   `회의유형` = `운영팀 온보딩` 태그가 붙은 행들이 대상. `date:회의일시:start` 기준 정렬해서 조회.
2. **서비스 분석 엑셀** — `C:\Users\user\Desktop\다우기술\00. 개인정리\서비스 분석 정리.xlsx`
   시트: 용어집 / 팀 분석 / 서비스 분석 / 00~12번 대메뉴별 시트 / Q&A / 비고

## 대상 (업데이트할 Notion 구조) — ⚠️ 매번 전부 확인, 하나라도 빼먹지 말 것
- 메인 페이지: "📘 사방넷 매뉴얼" (`https://app.notion.com/p/3d55ef838b3e8138a41edd25f7cb4573`)

  - 스키마: 메뉴명(title) / 대메뉴(select, 00~12) / 한줄설명(text) / 메뉴경로(text) / 상태(select: 작성완료/작성예정) / 관련용어·관련프로세스·관련메뉴·관련FAQ(relation)

  - **과거 실수 기록**: 2026-09-09에 05~08번 메뉴 사전만 업데이트하고 이 FAQ DB 업데이트를 빼먹어서 사용자에게 지적받음 → 앞으로 메뉴 사전을 업데이트하면 FAQ DB 반영 여부를 항상 체크리스트처럼 확인할 것.

## 무손실 반영 원칙 (빠짐없이 다 넣기)
- 온보딩 회의록의 내용은 **어떤 것도 임의로 생략하지 않는다.** 메뉴별로 재구성/정리하더라도, 회의록에 적힌 사실·정책·예외사항은 전부 어딘가(메뉴사전/프로세스/용어집/FAQ 중 하나)에 반영되어야 한다.
- 회의록과 엑셀 내용이 겹치면 **중복해서 두 번 쓰지 않고 유니크하게 한 번만** 쓴다 (문구는 더 명확한 쪽을 채택하거나 결합).
- 메뉴 페이지 작성을 마친 뒤에는 **원본 회의록으로 돌아가 한 줄씩 대조하는 검증 패스**를 거쳐, 요약 과정에서 빠뜨린 세부사항(예외 케이스, 수치, 참고사항, 질의응답)이 없는지 확인한다. 이 검증 없이 "다 반영했다"고 보고하지 않는다.

## 원천소스 결합 원칙 (우선순위 없음)
- 엑셀과 Notion 사이에 **고정된 우선순위는 없다.** 어떤 항목은 엑셀이 최신이고, 어떤 항목은 Notion이 최신일 수 있다 — 매번 실제 최신성/정확성을 따져서 판단할 것.
- 목표는 "둘 중 하나만 남기기"가 아니라 **엑셀 + 온보딩 회의록 + 기존 Notion 내용을 전부 결합**해서 최상의 매뉴얼을 만드는 것. 중복되는 내용만 한 번만 쓰고, 서로 다른 세부사항은 다 살린다.
- 두 소스의 사실관계(숫자, 목록 등)가 서로 다르면 임의로 한쪽을 정답으로 단정하지 말고, 근거가 확실하지 않으면 **사용자에게 확인**한다.
- 엑셀의 "*"로 시작하는 사이드노트/주석(예: "*카테고리간 상관관계", "가이드 안내: ...")이 Notion에 누락되기 쉬우므로, 업데이트 시 각 시트에서 "*"로 시작하는 줄들을 별도로 훑어 대응 Notion 페이지에 반영됐는지 확인할 것.

## 진행 절차
1. **최신 온보딩 회의록 확인**: 위 데이터소스에서 `회의유형 = '운영팀 온보딩'`인 행을 날짜 오름차순으로 조회. 지난번 업데이트 이후 새로 추가/수정된 회의록이 있는지 확인 (날짜, page_last_edited_at 기준).
2. **엑셀 재확인**: 서비스 분석 정리.xlsx의 관련 시트를 열어 회의록과 대조하고, 엑셀에만 있는 추가 정보가 없는지 확인. (주의: 엑셀이 다른 프로그램에서 열려있으면 `~$서비스 분석 정리.xlsx` 잠금 파일이 생기는데, 읽기 자체는 보통 가능)
3. **현재 Notion 매뉴얼 상태 파악**: 🗂️ 메뉴 사전 DB를 대메뉴별 `상태`(작성완료/작성예정)로 그룹핑 조회해서 무엇이 비어있는지, 새로 추가된 메뉴 항목과 이름이 겹치는 기존 항목이 없는지 확인.
4. **갭 도출**: 두 원천소스에서 다뤘지만 메뉴 사전 DB에 없는 메뉴, 또는 기존 항목인데 내용이 바뀐 부분을 목록화.
5. **구조 변경 여부 확인**: 다음의 경우 반드시 진행 전에 사용자에게 먼저 물어본다 (CLAUDE.md 0번 원칙과 동일 기조):
   - 새로운 대메뉴 카테고리를 추가해야 할 것 같은 경우
   - 기존 페이지 구조(개요/메뉴경로/진행방법 틀)를 바꾸고 싶은 경우
   - 작성 범위가 너무 커서(예: 여러 카테고리 동시) 우선순위 조정이 필요한 경우
   - 단순히 기존 항목에 몇 줄 추가/수정하는 수준이면 바로 진행해도 됨
6. **반영**: `notion-create-pages`(신규 메뉴)/`notion-update-page`(기존 메뉴 보강)로 작성. 신규 항목은 항상 기존 컨벤션(1메뉴=1행, 상태='작성완료')을 따른다.
7. **placeholder 정리**: 해당 대메뉴의 "OO (작성예정)" placeholder 행이 있다면, 실제 항목을 다 채운 뒤 제목 앞에 "⚠️ [삭제필요]"를 붙여 표시한다. (데이터소스 내 행은 API로 완전삭제가 안 되는 것으로 확인됨 — 표시만 해두고 사용자에게 수동 삭제 요청. 단, 어떤 페이지의 본문에 `<page url="...">`로 삽입된 서브페이지는 그 태그를 지우면서 `allow_deleting_content: true`를 주면 실제로 휴지통 이동/삭제가 됨 — 완전히 다른 메커니즘이니 혼동하지 말 것.)
8. **보고**: 무엇을 새로 추가/수정했는지, 어떤 placeholder를 정리 대상으로 표시했는지 요약해서 사용자에게 보고한다. 애매해서 반영하지 않은 내용이 있으면 그것도 알린다.

## 2026-09-09 UX 고도화 이후 추가된 컨벤션
- 메뉴/프로세스 페이지에 relation(관련FAQ·관련프로세스·관련용어·관련메뉴)이 하나라도 있으면, 본문 맨 아래 `## 관련 항목` 섹션을 만들고 `<mention-page url="...">` (self-closing 가능, 제목 자동 표시)로 노출한다. 속성 패널에만 있으면 사용자가 잘 못 본다.
- 🗂️ 메뉴 사전에 `검색키워드`(text), 📖 용어집에 `동의어`(text) 속성이 있다. 자주 헷갈리는 줄임말/오타/동의어가 있는 항목은 이 속성에 채워둘 것.
- 09~12번처럼 자료 부족으로 비워둔 대메뉴는 placeholder 페이지 본문에 "🚧 작성 예정 카테고리입니다 (자료 부족)" 안내문을 반드시 넣는다 — 빈 화면만 있으면 사용자가 "못 찾은 건가?" 오해함.
- ⚠️ **미완료 항목**: 관련 항목이 있는 68개 메뉴 중 23개를 확인했고 13개에 `## 관련 항목` 섹션을 추가함. 나머지 10개는 Notion API 사용량 제한(Query Data Source rate limit)으로 다음 실행 때 이어서 처리할 것.
- 🔴 **relation 속성은 "만들고 끝"이 아니라 "값까지 채워야" 한다** (2026-09-09 지적받음). 속성만 만들어놓고 값이 0건인 채로 메인 페이지에 "양방향으로 링크되어 있습니다"라고 써두는 바람에 거짓 안내가 됨. 작업 종료 전 반드시 아래 SQL로 채움률을 확인하고, 100%가 아니면 보고에 정확한 수치를 밝힐 것.
  `SELECT COUNT(*) total, SUM(CASE WHEN "관련용어" IS NOT NULL THEN 1 ELSE 0 END) term, SUM(CASE WHEN "관련메뉴" IS NOT NULL THEN 1 ELSE 0 END) menu, SUM(CASE WHEN "검색키워드" IS NOT NULL AND "검색키워드" != '' THEN 1 ELSE 0 END) kw FROM "collection://55181858-5bf8-4e75-ab75-47b6acbf46f6"`
- 🔴 **줄글보다 표를 우선한다** (2026-09-09 사용자 지시). 항목이 3개 이상 나열되거나 "항목–설명–주의사항" 구조면 불릿이 아니라 `<table>`로 작성할 것.
- 🔴 **`ALTER COLUMN "X" SET SELECT(...)`로 select 옵션을 재정의하면 기존 옵션이 사라지고 해당 행의 값이 null이 된다.** 옵션 이름을 바꿀 때는 변경 후 반드시 해당 행들을 다시 채워넣을 것 (2026-09-09에 FAQ `출처` 10건이 null이 되어 수동 복구함).
- **mermaid 노드 라벨 안에 대괄호 `[ ]`를 쓰지 말 것** — 파싱이 깨진다. 메뉴 경로는 `상품관리 › SKU상품관리`처럼 `›`로 표기.
- **운영/관리용 문서는 절대 공개 매뉴얼(사방넷 매뉴얼) 트리 안에 만들지 말 것.** 한 번 "🧩 대메뉴 신설 체크리스트" 페이지를 사방넷 매뉴얼 하위에 만들었다가, 실제 사용 주체(=이 스킬을 실행하는 나 자신)는 거기를 안 보고 SKILL.md만 보는데 정작 신규입사자·CS 응대자만 불필요한 운영 문서를 마주치는 배치 실수를 지적받고 삭제함. 운영 절차는 아래처럼 이 SKILL.md에만 적어둔다.
